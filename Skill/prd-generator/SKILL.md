# PRD Generator

基于已确认的设计分析和代码分析结果，生成标准化的产品需求文档（PRD）。

## ⚠️ 强制完整性原则

**【最高优先级】** 本技能执行必须遵循以下强制规则：

```
┌─────────────────────────────────────────────────────────────────────┐
│                    ❌ 禁止行为清单                                   │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  1. ❌ 禁止仅读取分析摘要                                           │
│     必须读取完整的分析报告原文                                       │
│                                                                      │
│  2. ❌ 禁止仅读取"模块名称"                                        │
│     必须读取每个模块的详细功能、API、核心逻辑                       │
│                                                                      │
│  3. ❌ 禁止仅读取部分页面/组件                                       │
│     必须读取分析报告中的每一个页面和组件                             │
│                                                                      │
│  4. ❌ 禁止跳过API详情                                              │
│     必须读取每个API的端点、参数、响应、用途                         │
│                                                                      │
│  5. ❌ 禁止仅凭摘要推断功能                                          │
│     必须基于分析报告中的详细描述生成PRD                             │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

## 核心原则

1. **必须基于确认结果**：仅基于用户已确认的分析结果生成文档
2. **内容来源透明**：每项内容必须标注来源（设计/代码/推断）
3. **待确认项标注**：无法确定的内容使用【待确认-XXX】格式
4. **AI推断标注**：AI推断的内容使用【AI推断-需验证】标注

## 前置条件检查

**【必须检查】** 在生成前必须确认：

```
❌ 禁止跳过此检查！

请确认以下前置条件：

1. [ ] 是否已完成设计分析并获得用户确认？
2. [ ] 是否已完成代码分析并获得用户确认？
3. [ ] 代码分析覆盖率是否为100%？
4. [ ] 是否已获得产品基本信息（产品名称、背景等）？

如果以上有任何一项为"否"，请先完成相应步骤。
```

## 输入要求

### 必需输入

| 输入 | 说明 | 来源 |
|------|------|------|
| 已确认的设计分析结果 | 完整报告，非摘要 | 用户确认 |
| 已确认的代码分析结果 | 完整报告，非摘要 | 用户确认 |

### 禁止输入（拒绝处理）

| 输入 | 原因 |
|------|------|
| 仅包含模块名称的分析摘要 | 无法生成详细PRD |
| 不完整的分析报告 | 覆盖率不足 |
| 仅目录结构 | 缺少功能描述 |

## 生成流程

### Step 1: 读取完整分析报告 ⚠️ 必须完整

```
┌─────────────────────────────────────────────────────────────────────┐
│                    读取完整性验证                                    │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  【代码分析报告】                                                   │
│  □ [✅] 已读取完整报告（[X]页）                                      │
│  □ [✅] 页面清单: [列出所有X个页面]                                  │
│  □ [✅] 模块清单: [列出所有X个模块]                                  │
│  □ [✅] API清单: [列出所有X个API]                                    │
│  □ [✅] 核心逻辑: [每个模块的代码片段]                               │
│                                                                      │
│  【设计分析报告】                                                    │
│  □ [✅] 已读取完整报告（[X]页）                                      │
│  □ [✅] 页面结构: [列出所有页面]                                     │
│  □ [✅] 组件清单: [列出所有组件]                                     │
│                                                                      │
│  ⚠️ 验证方式:                                                       │
│  生成的内容必须能在原始报告中找到对应描述                             │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

### Step 2: 整理信息映射表 ⚠️ 必须建立映射

必须建立**分析报告 → PRD章节**的完整映射：

```
┌─────────────────────────────────────────────────────────────────────┐
│                    信息映射表（必须完整）                            │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  【模块1】 → PRD第4章 4.1节                                        │
│  ├─ 页面1 → 功能点4.1.1                                             │
│  ├─ 页面2 → 功能点4.1.2                                             │
│  └─ API列表 → 功能点描述中的API引用                                  │
│                                                                      │
│  【模块2】 → PRD第4章 4.2节                                          │
│  ├─ 页面3 → 功能点4.2.1                                             │
│  └─ ...（必须覆盖所有模块）                                          │
│                                                                      │
│  【页面覆盖率】100% (分析X个 → PRD覆盖X个)                           │
│  【API覆盖率】100% (分析X个 → PRD引用X个)                           │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

### Step 3: 生成文档结构

使用 `PRD文档模板V1.0.md` 作为模板，按以下结构填充：

| 章节 | 内容来源 | 映射状态 |
|------|----------|----------|
| 项目概述 | 用户提供/分析报告 | ✅ |
| 术语与缩写解释 | 代码分析报告 | ✅ 全部映射 |
| 产品角色 | 设计+代码分析报告 | ✅ 全部映射 |
| 全局产品说明 | 设计分析报告 | ✅ 全部映射 |
| 产品功能性需求 | 代码分析报告 | ✅ 全部映射 |
| 权限 | 代码分析报告 | ✅ 全部映射 |
| 产品非功能性需求 | 通用标准 | - |
| 附录 | 用户补充 | - |

### Step 4: 【完整性校验】PRD ↔ 分析报告一致性

**【必须执行】** 生成PRD后，必须验证与原始分析报告的一致性：

```
┌─────────────────────────────────────────────────────────────────────┐
│                    【PRD完整性校验】                                 │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  模块覆盖检查:                                                      │
│  □ [✅] 分析报告中的模块[X]个 → PRD中的模块[X]个                    │
│  □ [❌] 遗漏模块: [模块名] → 必须补充！                             │
│                                                                      │
│  页面覆盖检查:                                                       │
│  □ [✅] 分析报告中的页面[X]个 → PRD中的功能点[X]个                  │
│  □ [❌] 遗漏页面: [页面名] → 必须补充！                             │
│                                                                      │
│  API覆盖检查:                                                       │
│  □ [✅] 分析报告中的API[X]个 → PRD中提及[X]个                      │
│  □ [❌] 遗漏API: [API名] → 必须补充！                               │
│                                                                      │
│  【逐项核对】                                                       │
│  模块1 (✅) | 模块2 (✅) | 模块3 (❌遗漏) | ...                     │
│                                                                      │
│  ⚠️ 任何遗漏都必须修正或标注！                                      │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

### Step 5: 【二次校验】PRD自洽性检查

#### 5.1 输入-输出一致性校验

```
校验清单：
□ [ ] PRD中的功能模块是否全部来自分析报告？
□ [ ] PRD中的页面列表是否与分析报告一致？
□ [ ] PRD中的API列表是否与分析报告一致？
□ [ ] 功能描述是否与分析报告中的描述匹配？
□ [ ] 术语定义是否与分析报告一致？
```

#### 5.2 二次校验报告

```
┌─────────────────────────────────────────────────────────────┐
│                    【PRD二次校验报告】                        │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  输入一致性:                                                 │
│  ✅ 通过: [N]项                                              │
│  ⚠️ 需核实: [N]项                                           │
│                                                              │
│  模块覆盖率: [X]% (遗漏[X]个模块)                            │
│  页面覆盖率: [X]% (遗漏[X]个页面)                            │
│  API覆盖率: [X]% (遗漏[X]个API)                             │
│                                                              │
│  【发现问题】                                                │
│  [1] ⚠️ 模块遗漏: [模块名] - 处理: [已补充/已标注]          │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### Step 6: 生成完整文档

```
---
生成完成！

### 文档统计
- 总章节数: 8章
- 功能模块数: [N]个（覆盖率[X]%）
- 页面覆盖数: [N]个（覆盖率[X]%）
- API覆盖数: [N]个（覆盖率[X]%）
- 已确认内容: XX项 ✅
- AI推断内容: XX项 ⚠️
- 待确认内容: XX项 ❓

### 与分析报告一致性
- 模块覆盖: [X]% ✅
- 页面覆盖: [X]% ✅
- API覆盖: [X]% ✅

### 下一步操作
1. 请检查文档内容
2. 补充【待确认】内容
3. 验证【AI推断】内容
4. 确认后转换为Word格式
---
```

## 内容标注规范

| 标注 | 格式 | 说明 |
|------|------|------|
| 已确认 | ✅ 【已确认-来源】 | 分析结果确认 |
| AI推断 | ⚠️ 【AI推断-需验证】 | AI合理推断，需验证 |
| 待确认 | ❓ 【待确认-XXX】 | 无法确定，需补充 |

## 注意事项

1. **禁止仅读摘要**：必须读取完整分析报告原文
2. **覆盖率必须100%**：任何遗漏都必须修正或标注
3. **映射表必须完整**：每个模块/页面/API都必须有映射
4. **校验必须执行**：输出前必须验证覆盖率
5. **二次校验必须执行**：校验失败内容必须修正或标注
