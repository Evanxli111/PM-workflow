# Operation Manual Generator

基于PRD文档和已确认的代码分析结果，生成标准化的系统操作手册。

## 核心原则

1. **必须基于确认结果**：仅基于用户已确认的分析结果或PRD生成文档
2. **内容来源透明**：每项操作步骤必须标注来源（PRD/代码/推断）
3. **待确认项标注**：无法确定的内容使用【待确认-XXX】格式
4. **AI推断标注**：AI推断的内容使用【AI推断-需验证】标注

## 二次校验机制

**【必须执行】** 生成操作手册后，必须进行前后依赖的二次校验，确保文档内容与输入一致，防止AI幻觉。

## 适用场景

- 基于PRD生成操作手册框架
- 基于代码分析结果生成操作步骤
- 生成标准化的用户指南
- 创建功能操作文档

## 前置条件检查

**【必须检查】** 在生成前必须确认：

```
❌ 禁止跳过此检查！

请确认以下前置条件之一：

1. [ ] 是否已有已确认的PRD文档？
2. [ ] 是否已有已确认的代码分析结果？
3. [ ] 是否已获得功能模块清单？

如果以上有一项为"是"，请提供相应文件或分析结果。
```

## 输入要求

### 必需输入（至少一项）

| 输入 | 说明 | 来源 |
|------|------|------|
| PRD文档 | 已确认的产品需求文档 | 用户提供 |
| 代码分析结果 | frontend-code-analyzer确认版 | 用户确认 |
| 功能模块清单 | 系统的功能模块列表 | 用户提供 |

### 可选输入

| 输入 | 说明 | 来源 |
|------|------|------|
| 产品基本信息 | 产品名称、系统描述 | 用户提供 |
| 特殊操作说明 | 特殊业务流程 | 用户提供 |

## 生成流程

### Step 1: 整理输入信息

从输入中提取功能模块和操作信息：

```
┌─────────────────────────────────────────────────────────────┐
│                    输入信息整理                              │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  【功能模块清单】                                           │
│  模块1: [名称] - [功能描述]                                │
│  模块2: [名称] - [功能描述]                                │
│                                                              │
│  【操作步骤来源】                                           │
│  - API分析: [API端点] → 操作步骤                           │
│  - 组件分析: [组件] → 操作路径                             │
│                                                              │
│  【待确认项】                                               │
│  - [项1]: [需要确认的内容]                                 │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### Step 2: 生成文档结构

使用 `操作手册模板V1.0.md` 作为模板：

| 章节 | 内容来源 | 标注要求 |
|------|----------|----------|
| 封面 | 用户提供 | - |
| 文档版本说明 | 用户提供 | - |
| 0.快速开始 | 用户提供 | 标注待确认 |
| 一、文档前言 | PRD/用户提供 | 标注来源 |
| 二、系统概述 | PRD/用户提供 | 标注来源 |
| 三、用户角色与权限说明 | PRD/代码分析 | 标注"已确认"/"待确认" |
| 四、功能模块一 | 代码分析 | 标注"已确认"/"AI推断" |
| 五、功能模块二 | 代码分析 | 标注"已确认"/"AI推断" |

### Step 3: 操作步骤编写规则

#### 已确认操作步骤
```
✅ 【已确认-代码】新增用户操作步骤：
1. 点击"用户管理"菜单
2. 点击"新增用户"按钮
3. 填写用户信息
4. 点击"保存"按钮
```

#### AI推断操作步骤
```
⚠️ 【AI推断-需验证】用户编辑操作步骤：
1. 点击"用户管理"菜单
2. 在用户列表找到目标用户
3. 点击"编辑"按钮
4. 修改用户信息
5. 点击"保存"按钮
```

#### 待确认操作步骤
```
❓ 【待确认-操作】用户删除是否需要二次确认？
```

### Step 4: 【二次校验】操作手册自洽性检查

**【必须执行】** 生成操作手册后，必须进行以下前后依赖校验：

#### 4.1 输入-输出一致性校验

检查操作手册内容是否与输入一致：

```
校验清单：
□ [ ] 操作手册中的功能模块是否全部来自已确认的输入？
□ [ ] 操作步骤中的功能点是否与代码分析中的API对应？
□ [ ] 权限描述是否与PRD中的权限定义一致？
□ [ ] 用户角色是否与分析结果中的角色一致？
□ [ ] 操作步骤中的按钮名称是否与界面实际名称匹配？
```

#### 4.2 步骤逻辑一致性校验

检查操作步骤内部逻辑是否合理：

```
校验清单：
□ [ ] 步骤顺序是否符合实际业务流程？
□ [ ] 每个步骤的前置条件是否已满足？
□ [ ] 操作步骤之间是否有遗漏？
□ [ ] 步骤描述是否与实际代码逻辑匹配？
□ [ ] 验证结果是否可实际验证？
```

#### 4.3 推断合理性校验

检查AI推断的操作步骤是否有依据：

```
校验清单：
□ [ ] [推断步骤1] 的推断依据是：[API/组件/设计]
□ [ ] [推断步骤2] 的推断依据是：[API/组件/设计]
□ [ ] 推断的按钮名称是否可能存在偏差？
□ [ ] 推断的操作路径是否可能不正确？
□ [ ] 是否存在将"可能"当作"确定"的情况？
```

#### 4.4 完整性校验

检查必要内容是否齐全：

```
校验清单：
□ [ ] 每个功能模块是否有完整的操作前提？
□ [ ] 每个功能点是否有可执行的步骤描述？
□ [ ] 是否有必要的注意事项和异常提示？
□ [ ] 敏感操作（删除/审核）是否有二次确认说明？
□ [ ] 操作手册与PRD文档的模块划分是否一致？
```

#### 4.5 PRD-操作手册一致性校验

如果同时有PRD和操作手册，检查两者一致性：

```
校验清单：
□ [ ] PRD中的功能点是否都有对应的操作步骤？
□ [ ] 操作手册中的功能模块是否与PRD一致？
□ [ ] 术语定义是否与PRD保持一致？
□ [ ] 权限描述是否与PRD一致？
```

#### 4.6 二次校验报告

完成校验后，输出校验报告：

```
┌─────────────────────────────────────────────────────────────┐
│                    【操作手册二次校验报告】                    │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  输入一致性:                                                 │
│  ✅ 通过: [N]项                                              │
│  ⚠️ 需核实: [N]项                                           │
│                                                              │
│  步骤逻辑一致性:                                             │
│  ✅ 通过: [N]项                                              │
│  ⚠️ 需核实: [N]项                                           │
│                                                              │
│  推断合理性:                                                 │
│  ✅ 合理: [N]项                                              │
│  ⚠️ 存疑: [N]项                                             │
│                                                              │
│  完整性:                                                     │
│  ✅ 完整: [N]项                                              │
│  ⚠️ 缺失: [N]项                                             │
│                                                              │
│  【发现的问题】                                              │
│  [1] ⚠️ "用户编辑"步骤第3步                                    │
│      - 操作手册: 点击"编辑"按钮                               │
│      - 代码分析: 按钮命名为"修改"                             │
│      - 处理: 已修正为"修改"                                   │
│                                                              │
│  [2] ⚠️ "批量删除"功能                                       │
│      - 操作手册: 包含批量操作                                 │
│      - 代码分析: 未发现批量API                                  │
│      - 处理: 标注【AI推断-需验证】                            │
│                                                              │
│  【AI幻觉风险项】                                            │
│  ⚠️ [项1]: [描述] - 依据: [来源], 风险: [描述]           │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### Step 5: 生成完整文档

```
---
生成完成！

### 文档统计
- 总章节数: 6章
- 功能模块数: [N个]
- 操作步骤数: [N个]
- 已确认内容: XX项 ✅
- AI推断内容: XX项 ⚠️
- 待确认内容: XX项 ❓

### 二次校验结果
- 输入一致性: ✅ 通过
- 步骤逻辑一致性: ✅ 通过
- 推断合理性: ⚠️ X项存疑
- 完整性: ⚠️ X项缺失

### 下一步操作
1. 请检查文档内容
2. 补充【待确认】操作步骤
3. 验证【AI推断】操作步骤
4. 确认后转换为Word格式
---
```

## 注意事项

1. **禁止捏造操作**：操作步骤必须有代码或PRD依据
2. **透明标注**：所有步骤必须标注来源和置信度
3. **可执行性**：步骤必须具体可操作，避免模糊描述
4. **验证方法**：每个功能点必须包含验证方法
5. **二次校验必须执行**：校验失败内容必须修正或标注
