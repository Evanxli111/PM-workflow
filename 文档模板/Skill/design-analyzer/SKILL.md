# Design Analyzer

基于Figma原型（Figma链接/截图）和需求文档，生成结构化的设计分析报告，为PRD文档提供设计层面的依据。

## ⚠️ 强制完整性原则

**【最高优先级】** 本技能执行必须遵循以下强制规则，禁止偷工减料：

```
┌─────────────────────────────────────────────────────────────────────┐
│                    ❌ 禁止行为清单                                   │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  1. ❌ 禁止仅凭主观想象补充设计细节                                  │
│     必须基于 Figma 链接 或 截图中的实际元素进行分析                   │
│                                                                      │
│  2. ❌ 禁止跳过任何页面的分析                                        │
│     必须对所有页面逐一分析，不遗漏                                    │
│                                                                      │
│  3. ❌ 禁止将"推测"当作"确认"                                        │
│     无法确定的设计必须标注【待确认】或【来源：AI推断】               │
│                                                                      │
│  4. ❌ 禁止忽略页面之间的跳转关系                                    │
│     必须分析完整的页面流程                                            │
│                                                                      │
│  5. ❌ 禁止遗漏组件/元素的分析                                        │
│     表单、列表、按钮等必须逐一记录                                    │
│                                                                      │
│  6. ❌ 禁止忽略 Figma 链接可获取的精确属性                           │
│     应充分利用 Figma 链接获取精确的组件属性                           │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

## 核心原则

1. **必须基于设计证据**：分析内容必须能在 Figma 链接 或 截图中找到依据
2. **设计意图透明**：区分"可见设计"与"推断意图"
3. **待确认项标注**：无法确定的内容使用【待确认-XXX】格式
4. **二次校验机制**：分析完成后必须进行自洽性检查
5. **人工确认机制**：AI分析结果必须经过用户确认后才能用于生成文档

### 设计证据来源

| 输入类型 | 证据类型 | 说明 |
|----------|----------|------|
| **Figma 分享链接** | 结构化设计数据 | 组件属性、布局参数、交互关系 |
| **原型截图** | 视觉证据 | 页面布局、元素可见性、样式外观 |

**原则**：无论使用哪种输入，分析结论都必须有明确的来源依据，禁止凭空想象。

## 适用场景

- 用户已完成Figma原型设计
- 需要从原型中提取页面结构和功能布局
- 需要解读设计意图和交互逻辑
- 需要为PRD文档提供设计层面的输入

**【必须检查】** 开始分析前，必须确认以下检查项：

```

请确认以下前置条件：

1. [ ] 是否提供了 Figma 分享链接 或 原型截图？

   - 原型截图：确保截图覆盖所有关键页面
```

### Step 2: 页面结构分析 ⚠️ 必须逐一分析

对于**每个**页面，必须提取：

| 信息项 | 说明 | 必填 | Figma来源 | 截图来源 |
|--------|------|------|-----------|----------|
| 页面名称 | 与截图命名一致 | ✅ | 直接获取 | 截图标题 |
| 页面编号 | 建议格式：P01, P02... | ✅ | 用户提供 | 用户提供 |
| 路由推断 | 推测的URL路径 | ⚠️ | 页面命名 | 页面命名 |
| 主要功能 | 页面承担的核心功能 | ✅ | 组件分析 | 视觉布局 |
| 功能元素 | 包含哪些组件/元素 | ✅ | 精确组件 | 可见元素 |
| 布局结构 | 页面如何分区布局 | ✅ | 自动布局 | 视觉分区 |
| 交互元素 | 按钮、表单等可交互元素 | ✅ | 组件属性 | 可见元素 |
| 状态设计 | 有哪些页面状态 | ⚠️ | 组件变体 | 设计推断 |
| 组件属性 | 组件的具体属性值 | ✅ | 精确值 | 近似值 |

**Figma 链接 vs 原型截图 信息获取对比**：

| 信息类型 | Figma 链接 | 原型截图 |
|----------|------------|----------|
| 页面名称 | ✅ 精确 | ✅ 需命名 |
| 组件类型 | ✅ 精确 | ⚠️ 需推断 |
| 组件属性 | ✅ 精确值 | ⚠️ 近似值 |
| 布局结构 | ✅ 精确 | ✅ 视觉可见 |
| 交互关系 | ✅ 可追踪 | ⚠️ 需推断 |
| 变体/状态 | ✅ 完整 | ⚠️ 有限 |

#### 10.3 推断合理性校验

```
校验清单：

```

## 注意事项

1. **禁止捏造设计细节**：所有分析内容必须基于 Figma链接 或 截图中的设计证据
