# Frontend Code Analyzer

分析前端代码结构，提取业务逻辑和技术实现，为PRD文档和操作手册提供代码层面的依据。

## ⚠️ 强制完整性原则

**【最高优先级】** 本技能执行必须遵循以下强制规则，禁止偷工减料：

```
┌─────────────────────────────────────────────────────────────────────┐
│                    ❌ 禁止行为清单                                   │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  1. ❌ 禁止仅分析目录结构                                           │
│     必须读取每个文件的实际代码内容                                   │
│                                                                      │
│  2. ❌ 禁止仅提取文件名称作为功能                                   │
│     必须分析代码逻辑，理解实际功能                                   │
│                                                                      │
│  3. ❌ 禁止跳过任何页面或组件                                       │
│     必须对所有页面逐一分析                                           │
│                                                                      │
│  4. ❌ 禁止使用"模块名"推断功能                                     │
│     必须读取具体代码，提取实际业务逻辑                               │
│                                                                      │
│  5. ❌ 禁止跳过API详情分析                                           │
│     必须分析每个API的请求/响应/业务用途                             │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

## 核心原则

**人工确认机制**：AI分析结果必须经过用户确认后才能用于生成文档。

**二次校验机制**：分析完成后必须进行自洽性检查。

**强制完整性机制**：必须完整扫描所有代码，禁止选择性分析。

## 适用场景

- 用户已从Git获取前端代码
- 需要提取业务功能模块
- 需要梳理API接口和数据模型
- 需要提取用户操作流程
- 需要编写操作手册中的操作步骤

## 输入方式

用户提供前端代码的本地路径，技能将使用code-explorer分析代码结构。

## 分析流程（必须按顺序执行）

### Step 1: 项目扫描 ⚠️ 必须完整

使用code-explorer扫描项目结构，**必须扫描所有文件**：

```
┌─────────────────────────────────────────────────────────────────────┐
│                    扫描报告（必须完整）                              │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  扫描范围:                                                         │
│  □ [✅] src/                                                       │
│  │   □ [✅] pages/ 或 views/  ← 必须逐一列出所有页面               │
│  │   │   □ [✅] UserList.tsx                                       │
│  │   │   □ [✅] UserDetail.tsx                                     │
│  │   │   □ [✅] OrderList.tsx                                      │
│  │   │   □ [✅] OrderDetail.tsx                                    │
│  │   │   ... (必须列出全部)                                         │
│  │   │                                                               │
│  │   □ [✅] components/  ← 必须分析每个组件                       │
│  │   │   □ [✅] Button.tsx                                         │
│  │   │   □ [✅] Table.tsx                                          │
│  │   │   ... (必须列出全部)                                         │
│  │   │                                                               │
│  │   □ [✅] services/ 或 api/  ← 必须分析每个API                 │
│  │   │   □ [✅] user.ts                                            │
│  │   │   □ [✅] order.ts                                           │
│  │   │   ... (必须列出全部)                                         │
│  │   │                                                               │
│  │   □ [✅] stores/ 或 contexts/                                    │
│  │   □ [✅] router/                                                │
│  │   □ [✅] types/ 或 interfaces/                                  │
│  │   □ [✅] constants/                                             │
│  │                                                                       │
│  统计: 页面[X]个 | 组件[X]个 | API[X]个 | 其他[X]个                   │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

**【强制】必须读取每个文件的实际内容，禁止仅凭文件名判断功能！**

### Step 2: 页面分析 ⚠️ 必须逐一分析

对于**每个**页面组件，必须读取代码并提取：

| 信息项 | 说明 | 必填 |
|--------|------|------|
| 页面名称 | 文件名/组件名 | ✅ |
| 路由路径 | router中的路径 | ✅ |
| 功能描述 | **从代码提取的实际功能**，不是文件名推断 | ✅ |
| 主组件 | 页面主组件代码 | ✅ |
| 子组件 | 页面使用的子组件 | ✅ |
| 状态管理 | 使用的状态管理方式 | ✅ |
| API调用 | 调用的API列表 | ✅ |
| 核心逻辑 | **核心业务逻辑代码片段** | ✅ |

**示例 - 正确做法**：
```
❌ 错误: "UserList.tsx" → "用户列表页"（仅文件名）

✅ 正确: "UserList.tsx" → 
  - 路由: /users
  - 功能: 展示用户列表、支持分页搜索、批量选择、导出Excel
  - API: getUserList, deleteUser, exportUsers
  - 核心逻辑: 
    - useEffect(() => { fetchUserList() }, [page])
    - setSelectedRows(rowKeys)
    - exportToExcel(selectedRows)
```

### Step 3: API分析 ⚠️ 必须分析每个API

对于**每个**API文件，必须提取：

| 信息项 | 说明 | 必填 |
|--------|------|------|
| API端点 | 完整URL路径 | ✅ |
| 请求方式 | GET/POST/PUT/DELETE | ✅ |
| 请求参数 | **从代码提取的实际参数** | ✅ |
| 响应数据 | **从代码提取的实际响应结构** | ✅ |
| 业务用途 | **从代码注释和调用上下文理解用途** | ✅ |
| 错误处理 | 错误码和错误处理逻辑 | ✅ |

### Step 4: 组件分析 ⚠️ 必须分析关键组件

对于**每个**组件，必须提取：

| 信息项 | 说明 | 必填 |
|--------|------|------|
| 组件名称 | PascalCase命名 | ✅ |
| Props定义 | **实际Props类型和用途** | ✅ |
| 组件用途 | **从代码理解实际用途** | ✅ |
| 状态定义 | useState/useReducer的实际状态 | ✅ |
| 交互行为 | onClick/onChange等事件处理 | ✅ |

## 输出格式

### 确认后的完整分析报告

必须包含：

1. **分析覆盖率统计**：文件总数、分析数、覆盖率百分比
2. **完整功能模块列表**：所有模块，不遗漏
3. **完整API清单**：所有API，不遗漏
4. **完整页面清单**：所有页面，不遗漏
5. **核心代码片段**：关键业务逻辑
6. **二次校验记录**：校验通过项、需核实项

1. **禁止仅分析目录结构**：必须读取每个文件的代码
2. **禁止仅凭文件名推断**：必须从代码提取实际功能
